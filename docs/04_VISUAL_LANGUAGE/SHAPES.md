# BOOKLOOM SHAPE SYSTEM

Version: 1.0

Status: Approved

Priority: CRITICAL

---

# PURPOSE

Shapes define the physical language of BookLoom.

Every interface element should feel like it belongs to the same family.

Users should never consciously notice the shapes.

Instead, they should experience the product as calm, refined, and intentionally crafted.

---

# DESIGN PHILOSOPHY

BookLoom follows architectural geometry.

Simple.

Balanced.

Timeless.

Every shape exists to improve usability.

Never to show creativity.

---

# DESIGN INSPIRATION

Luxury books

Modern architecture

Editorial layouts

Premium stationery

Apple hardware

Minimal interior design

Museum signage

Japanese minimalism

---

# CORE PRINCIPLES

Geometry should be

Simple

Consistent

Predictable

Soft

Quiet

Elegant

Never experimental.

---

# PRIMARY SHAPE

Rounded Rectangle

This is the default shape for nearly every component.

Examples

Cards

Inputs

Buttons

Dialogs

Dropdowns

Tooltips

Panels

Menus

Tables

---

# SECONDARY SHAPES

Circle

Used only for

Avatars

Status indicators

Loading indicators

Profile photos

Icon containers

---

# LINEAR SHAPES

Used for

Dividers

Progress bars

Selection indicators

Timelines

Focus guides

Always thin.

Never decorative.

---

# GEOMETRIC LANGUAGE

Horizontal alignment dominates.

Vertical rhythm creates hierarchy.

Diagonal compositions are extremely rare.

---

# CORNER PHILOSOPHY

Corners communicate personality.

Sharp corners

Corporate

Aggressive

Soft corners

Calm

Premium

Human

BookLoom always prefers soft corners.

---

# RADIUS HIERARCHY

Tiny

Internal chips

Small

Inputs

Medium

Buttons

Cards

Large

Dialogs

Extra Large

Marketing imagery

Never mix unrelated radii on the same screen.

---

# CIRCULAR ELEMENTS

Allowed

Profile images

Status dots

Loading

Icons inside circles

Forbidden

Circular cards

Circular menus

Circular dialogs

Circular navigation

Circular dashboards

---

# PILLS

Allowed

Tags

Labels

Status

Filters

Small actions

Not allowed

Entire page layouts

Primary cards

Editor canvas

---

# DIVIDERS

Purpose

Separate information.

Never decorate.

Appearance

Ultra thin.

Low contrast.

Large surrounding whitespace.

---

# CONTAINERS

Containers should frame content.

Never trap it.

Padding creates comfort.

Borders create definition.

Spacing creates hierarchy.

---

# NEGATIVE SPACE

Negative space is considered a shape.

Large empty areas improve readability.

Never fill whitespace simply because it exists.

---

# ASYMMETRY

Allowed only

Marketing pages

Editorial hero sections

Illustrations

Application UI remains balanced and structured.

---

# SYMMETRY

Preferred for

Forms

Dashboard

Settings

Billing

Editor

Tables

Navigation

Predictability improves usability.

---

# ICON FRAMES

Icons normally appear without containers.

Container shapes are reserved for

Feature cards

Illustrations

Marketing

Notifications

---

# IMAGE FRAMES

Book covers

Slight radius

Photography

Medium radius

Illustrations

Variable

Never crop images into circles unless they are avatars.

---

# BUTTON SHAPES

Follow Button component specification.

Never invent custom shapes.

Never create floating circular CTA buttons without documented approval.

---

# CARD SHAPES

Flat.

Balanced.

Comfortable.

Consistent radius.

No angled edges.

No cut corners.

No unusual silhouettes.

---

# MODALS

Large rounded rectangle.

Centered.

Maximum readability.

Never use full-screen modal styling unless required on mobile.

---

# DRAWERS

Rectangular.

Soft leading edge.

Flush against screen edge.

---

# TOOLTIPS

Compact rounded rectangle.

No speech bubble tails.

Arrow indicators remain subtle.

---

# TABLES

Rectangular structure.

Rows create rhythm.

Avoid excessive rounded shapes inside data-heavy layouts.

---

# EDITOR

Writing canvas remains rectangular.

Margins define reading comfort.

Shape should disappear behind the content.

---

# AI PANEL

Same geometry as every other panel.

No futuristic shapes.

No speech-bubble interface.

No chat-app imitation.

---

# FORBIDDEN SHAPES

Hexagons

Stars

Diamonds

Speech bubbles

Blob shapes

Organic liquid forms

Abstract polygons

Irregular cards

Explosive bursts

Decorative frames

Unless specifically used in illustrations.

---

# ACCESSIBILITY

Shapes must support

Recognition

Touch targets

Keyboard navigation

Visual grouping

Never reduce usability for visual novelty.

---

# RESPONSIVE

Geometry remains consistent.

Only spacing changes.

Shape language should never change across breakpoints.

---

# PERFORMANCE

Prefer CSS border-radius.

Avoid SVG masking.

Avoid clipping paths.

Avoid complex geometric rendering.

---

# REVIEW CHECKLIST

✓ Consistent radius

✓ Soft geometry

✓ Predictable layouts

✓ Minimal visual complexity

✓ Accessible

✓ Responsive

✓ Editorial identity maintained

---

# FINAL RULE

A BookLoom interface should feel carefully composed, not artistically decorated.

If users notice the geometry before they notice the content,

the geometry is too expressive.
